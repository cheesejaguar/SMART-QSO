# SMART-QSO Ground Software Tools

**Document ID**: SMART-QSO-GND-000
**Version**: 1.3
**Date**: 2026-11-03

Ground segment utilities for SMART-QSO satellite operations. Governing documents: `docs/BASELINE_PARAMETERS.md`,
`docs/ground/GROUND_STATION_DESIGN.md` (SQSO-GND-001), `docs/ground/ORBIT_DETERMINATION_AND_EPHEMERIS.md`
(SQSO-GND-002), `docs/interfaces/TELECOMMAND_AUTHENTICATION.md` (SQSO-ICD-013) and `docs/BEACON_SPEC.md`.

Besides the tools below, this directory holds their modules: `command_dictionary.py` (generated by
`scripts/gen_command_dictionary.py` from `software/flight/command_dictionary.json`; do not edit), `gnss_frame.py`,
`orbit_dynamics.py`, `orbit_determination.py`, `orbit_frames.py` and `ephemeris_products.py`. The decoder, telecommand,
key and GNSS-frame tools use `sqso_protocol`, the flight software's Rust wire formats (`pip install ./software/rust/sqso-py`
from the repository root; it is not on PyPI). The parent directory `software/ground/` holds `telemetry_display.py` (a
library) and the test suites for both directories.

## Tools Overview

### beacon_decoder.py
The ground decoder of the spacecraft's text frames (the only one; the earlier decoder in `software/ground/` is
removed). Each record is one JSON object per line:

| Frame | Record | What is decoded |
|-------|--------|-----------------|
| Beacon `de KK6GDB-11: <text> \| T=… M=… SOC=… BV=… SUN=… RF=… QSO=…` | `beacon` | Call sign, text and every field of `docs/BEACON_SPEC.md` §3–§4; `-` is `null` (not measured, never zero); `T` is seconds since the last OBC boot, not UTC |
| `HK1 …`, `HK2 …` | `hk1`, `hk2` | Every field of SQSO-TLM-001 §4.4 and §4.4.1, by name in engineering units (`soc_pct`, `battery_v`, `battery_temp_c`, `rate_x_dps`, `sun_x` …) beside the raw `KEY=value` text. A text longer than one frame (HK1 at its widest is 341 bytes, two frames; HK2 573 bytes, three) is merged from its frames by their `HKn N=<seq>` head and given out when the frame with its last field (`AD`, `SN`) arrives; a text whose frames stop is given out with `"complete": false` and its `missing_keys` |
| `GNS …` | `gns` | Through `gnss_frame.py` |
| `ack KK6GDB-11: C=… R=… N=…` | `ack` | Counter, result, days since contact |
| `HKD …` (binary stored records) | `hkd` | Recognised, not decoded (SQSO-ICD-005 §5.6) |

A frame is accepted with its flags and FCS (as on the air), from the address field through the FCS, or without the FCS
(as a KISS TNC delivers it); with flags the FCS must check. AX.25 parsing and KISS framing are `sqso_protocol`'s
(`ax25_parse_ui`, `KissDecoder`). The tests (`software/ground/tests/test_beacon_decoder.py`) decode frames made by the
flight formatters, including the widest HK1 and HK2 texts: `software/ground/tests/fixtures/flight_frames.txt`, written
and kept current by `software/rust/sqso-fsw/tests/ground_frames.rs`.

```bash
# Live, from Direwolf's KISS TCP port, logging every frame received (JSON lines {rx_utc, frame_hex})
python beacon_decoder.py --kiss-tcp localhost:8001 --log beacon_log_YYYYMMDD_HHMMSS.jsonl

# Live from a KISS serial TNC (set the line up first, e.g. stty -F /dev/ttyUSB0 9600 raw)
python beacon_decoder.py --kiss-file /dev/ttyUSB0 --log frames.jsonl

# Afterwards: a frame log (one frame per line: hex as the last word, or JSON with frame_hex)
python beacon_decoder.py -f beacon_log_YYYYMMDD_HHMMSS.jsonl -o decoded.jsonl

# One frame in hex, or a log on standard input
python beacon_decoder.py "7E86A2404040406096966C8E888477..."
cat frames.txt | python beacon_decoder.py --stdin
```

`--parts` also prints each housekeeping frame before it is merged. Not yet done: limit checking against SQSO-TLM-001
§5 and names for the enumerated values (`RST`, `MODE`, `AM` …), which are given as numbers.

### fl_update_builder.py
Builds FL-UPDATE v0.2 frames for federated learning model updates. Ground-side research only: community model updates are not in the flight baseline, and the flight software has no receiver for these frames (SW-11).

```bash
# Build frames from model data
python fl_update_builder.py -i model_gradients.bin -o frames/

# Build with manifest
python fl_update_builder.py -i weights.bin --name "qso-priority" --version "1.2.0"

# Validate a frame
python fl_update_builder.py --validate frame_001.bin
```

### telecommand_builder.py
Builds authenticated uplink telecommands (SQSO-ICD-013, `docs/interfaces/TELECOMMAND_AUTHENTICATION.md`).
The key file holds 64 hex characters and must be mode 600. Keys are never committed to any repository.
The counter file is shared by every telecommand station; each counter is reserved on disk before its frame is produced.

```bash
# List the command dictionary
python telecommand_builder.py --list

# Latch the transmitter off (47 CFR 97.207(b))
python telecommand_builder.py TX_DISABLE --key-file /secure/sqso.key --counter-file /secure/sqso.counter

# Set the beacon interval to 60 s, writing the binary frame to a file
python telecommand_builder.py SET_BEACON --args 003C --key-file /secure/sqso.key \
    --counter-file /secure/sqso.counter --out set_beacon.bin

# Wrap in an AX.25 UI frame and KISS-encode it for a TNC (spacecraft KK6GDB-11; use your own station's call sign as the source)
python telecommand_builder.py TX_DISABLE --key-file /secure/sqso.key \
    --counter-file /secure/sqso.counter --ax25 KK6GDB-11 N0CALL --kiss --out tx_off.kiss
```

Keep one counter file per key (operational and recovery), and start a new operational counter file after each KEY_ROTATE.

With two or more telecommand stations, counters come from UTC (SQSO-ICD-013 §5.2.1):
`counter = 4 × (UTC s since 2028-01-01) + station index`. Each station keeps its own counter file and a
`station.json` with its index; the builder refuses unless the kernel reports the clock synchronised with a maximum
error ≤ 0.5 s, and never goes below its own last counter or the newest acknowledged counter of any station.

```bash
echo '{"station": "KK6GDB", "station_index": 0}' > station.json
python telecommand_builder.py NOP --key-file /secure/sqso.key --counter-file /secure/op.ctr \
    --counter-from-utc --station-config station.json --newest-ack 2915678401 --ax25 KK6GDB-11 KK6GDB --kiss
```

### key_provision.py
Generates a telecommand key set and the GSE frames that load it through the umbilical (integration only; SQSO-ICD-013 §9.2).
Key files and frame files contain secrets: they are written mode 600 and are never overwritten. Keep `recovery.key` offline.

```bash
python key_provision.py generate --dir /secure/sqso-keys
python key_provision.py frames --dir /secure/sqso-keys --out /secure/frames.bin   # send over the umbilical, then delete
python key_provision.py zeroize --out /secure/zeroize.bin
python key_provision.py arm-flight --help   # frame that re-arms the 45-minute RF silence and the deployment sequence
                                            # (last powered action before shipping)
```

### ephemeris_tool.py
Operator ephemeris from the onboard GNSS fixes (SQSO-GND-002, `docs/ground/ORBIT_DETERMINATION_AND_EPHEMERIS.md`):
decodes the GNSS state frames from beacon and telemetry archives (`gnss_frame.py`), fits the orbit by batch least
squares with an estimated drag scale (`orbit_dynamics.py`, `orbit_determination.py`), and writes a CCSDS OEM 3.0 with a
covariance per record, a TLE fitted with SGP4, and a report with residuals and the quality flag (GOOD, FAIR, POOR).

```bash
python ephemeris_tool.py --frames gnss_48h.jsonl --out-dir eph/ --gravity-file EGM2008.gfc --gravity-degree 12 \
    --object-id 2028-123A --norad-id 99999                        # ITRF2000 OEM
python ephemeris_tool.py --frames gnss_48h.jsonl --out-dir eph/ --frame EME2000 --dut1 0.071
```

Exit status 0 (GOOD or FAIR: upload), 2 (POOR: files prefixed NOT-FOR-UPLOAD_), 3 (FAIL: no products).
`gnss_simulation.py` makes simulated fixes for rehearsals.

### pass_predictor.py
Predicts satellite passes and calculates QSO fairness metrics. Without `--tle` it generates synthetic demonstration
passes from a generic 400 km orbit, not the 475 km SSO baseline (`docs/BASELINE_PARAMETERS.md` §3); use a TLE for any
real prediction.

```bash
# Predict passes for a single station
python pass_predictor.py --lat 37.4 --lon -122.0 --duration 48

# Analyze fairness across multiple stations
python pass_predictor.py --stations stations.json --fairness

# Use TLE for accurate prediction (requires sgp4)
python pass_predictor.py --lat 37.4 --lon -122.0 --tle smart-qso.tle
```

## Installation and tests

From the repository root (as `.github/workflows/program-checks.yml` does):

```bash
pip install ./software/rust/sqso-py
pip install -r software/ground/tools/requirements.txt
python -m pytest -q software/ground/tests
```

## Requirements

- Python 3.9+
- numpy (the ephemeris tool; optional for the pass predictor)
- sgp4 (the ephemeris tool's TLE; accurate pass prediction)
- `sqso_protocol` (built from `software/rust/sqso-py`)

agreed yet, `docs/BASELINE_PARAMETERS.md` §1):

```json
    {
      "name": "W6YX",
      "latitude": 37.4275,
      "longitude": -122.1697,
      "altitude": 30,

    {
      "name": "K6LRG",
      "latitude": 38.5449,
      "longitude": -121.7405,
      "altitude": 15,
      "grid_square": "CM98qm"
    }
  ]
}
```
