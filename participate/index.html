Licensing and frequencies

SMART-QSO would be an FCC Part 97 amateur space station. The bands below are the ones the project will ask the IARU to coordinate a frequency in; they are not assigned frequencies. Downlink in 145.800–146.000 MHz (not 145.825 MHz); uplink requested in 435.222–435.778 MHz, or else 436.222–436.500 MHz. SQSO-BL-001 §7

For amateur radio operators, once it flies

The planning launch date is about 2028-11-01. If it launches and is commissioned, any licensed amateur with an FM handheld or mobile rig and a small Yagi could work other stations through the transponder, in sunlit passes when the power gates open. Community and SatNOGS stations would receive and decode the beacon, with logs published openly. CONOPS.md §6

The beacon is a 1200 bps AFSK AX.25 UI frame from KK6GDB-11 with one line of plain text and a telemetry tail; every value in it is a measurement, and an unmeasured field is sent as -. BEACON_SPEC.md §1–§4

de KK6GDB-11: <text> | T=<s since boot> M=<SAFE|IDLE|ACTIVE> SOC=<%> BV=<V.d> SUN=<0|1> RF=<0|1> QSO=<count>

A decoder is in software/ground/tools/beacon_decoder.py.

Help wanted now

Telecommand stations

The mission needs at least two designated amateur stations at least 1,000 km apart, each able to command the spacecraft alone, with written agreements by 2027-01-05. None is agreed yet. A station must radiate at least 64 dBm EIRP toward the spacecraft on 70 cm and commands only above 10° elevation.

SQSO-BL-001 §1 CONOPS.md §6 Ground station design

Independent reviewers

The CDR 2026 review was done by AI reviewers. The independent PDR, planned for 2027-01-12, needs a chair and at least two reviewers from outside the team, covering systems, electrical and RF, and flight software.

SQSO-SCH-001 §5 DA-03

PCB layout

The boards exist as schematics. The plan needs two PCB layout designers (KiCad, IPC-6012 Class 3) to start in January 2027; with one, the schedule loses its float.

SQSO-SCH-001 §5 DA-04

Review the documents

Every claim the project makes is in the repository with its evidence. Reading a document against its sources and opening an issue for what is wrong is the most useful contribution of all.

Software

Flight software in Rust (no_std, unsafe forbidden in the protocol and logic crates), the Jetson payload and the ground tools in Python. Tests run in CI.

software/rust Ground tools

Start with CONTRIBUTING.md: discuss in an issue first, then a pull request with tests. The project follows a code of conduct and a governance document; report security problems as SECURITY.md says. Amateur operation of the station is unpaid. SQSO-BL-001 §1
