## 1. Purpose

This matrix gives, for every requirement in the mission, system and software specifications, the verification
method, the planned verification event and its date, the procedure or analysis that will verify it, and the status.
It satisfies the CDR expectation that "the product verification and product validation requirements and plans are
complete" (NPR 7123.1D Table G-7, success criterion 5) by making the plan checkable: §3 is generated from the
specifications, so a requirement without a planned event cannot be added unnoticed.

## 2. Verification Methods

| Code | Method | Description |
|------|--------|-------------|
| A | Analysis | Mathematical analysis, simulation, modeling |
| D | Demonstration | Functional demonstration of capability |
| I | Inspection | Visual examination, measurement, review of records |
| T | Test | Formal test with documented procedure and pass criteria |
| V | Validation | Mission objectives, judged against the success criteria (`docs/mission/MISSION_SUCCESS_CRITERIA.md`) |

## 3. Requirements, Methods, Events and Status

Sections 3.1 to 3.5 are generated by `software/simulation/cdr/pm/gen_vcrm.py` from the three specifications (the same
rows as `docs/verification/RTM.csv`) and the event plan in that script. The event dates are the early dates of the
critical-path schedule in `mission/SCHEDULE.md` (`software/simulation/cdr/pm/schedule_cpm.py`). Run
`python3 software/simulation/cdr/pm/gen_vcrm.py` after changing a specification, and `--check` to confirm the block is
current.
